# Семинар 3. Домашнее задание: команда агентов

## Задача

Доработайте `polygon3/negotiation_agent.py`, чтобы команда из трёх агентов
составляла план закупки и доставки по заявке заказчика. Один и тот же файл
запускается в трёх отдельных процессах. У каждой роли свои документы и память:

| Роль | Какие сведения ей доступны |
|---|---|
| Координатор (`coordinator`) | Заявка: товары, количества, разрешённые замены, обязательные свойства, адрес, срок и бюджет. |
| Снабжение (`supply`) | Предложения поставщиков: цены, остатки, упаковки, склады и время готовности товаров. |
| Логистика (`logistics`) | Рейсы: маршруты, расписание, вместимость, допустимые категории груза и стоимость перевозки. |

Организуйте обмен сообщениями между ролями и выбор общего плана. Каждая
строка заявки должна быть целиком закуплена по одному предложению поставщика
и отправлена одним прямым рейсом. План должен соблюдать условия по товарам и количеству,
наличию и упаковкам, складам, массе, категориям груза, срокам и общему бюджету.

Если допустимого плана нет, координатор может сдать ответ `infeasible`.
Сервер проверит это утверждение своим решателем. Остановка поиска без
решения не считается доказательством невозможности.

## Что нужно реализовать

- Прочитать документы своей роли и извлечь из текста необходимые данные.
- Передать другим ролям сведения, которые нужны для общего решения.
- Выбрать совместимые закупку и перевозку и проверить весь план перед сдачей.
- Повторить проверку после обновления документов. Старые данные и ответы
  нельзя использовать как подтверждение новой редакции.
- Обработать повторные и запоздалые сообщения и завершить работу в пределах
  ресурсов эпизода.

В заготовке уже есть чтение документов, обращение к модели, арифметические
проверки и учебный протокол переговоров. Вы можете дорабатывать код внутри
рабочего файла. Функция должна сохранить интерфейс
`act(observation, memory)` и возвращать пару `(action, memory)`.
Изменения локального движка и других модулей вместе с решением не загружаются.

В одном эпизоде всей команде доступны 9 вызовов модели, 120 действий и
24 сообщения. Полные форматы, правила поставки и ограничения размеров
описаны в [техническом ТЗ](../polygon3/README.md).

## Как проверить

Все команды выполняются из корня репозитория `seminars/`.
Проверьте программу на открытых случаях, например:

```bash
python -m polygon3.negotiation_probe --case case_001 --agent polygon3/negotiation_agent.py --output artifacts/polygon3/negotiation/check_001.json
```

```bash
python -m polygon3.negotiation_probe --case case_020 --agent polygon3/negotiation_agent.py --output artifacts/polygon3/negotiation/check_020.json
```

Заготовка содержит ошибки; ненулевой код выхода второго запуска до исправления
ожидаем. Посмотрите в JSON, какой план сдан и какое условие нарушено.
[Материалы практики](../polygon3/практика.md) содержат упражнения и команды
для отдельных проверок.

Эти запуски используют `scripted`, который возвращает готовые факты без
обращения к модели. Отдельно проверьте извлечение на живой модели:

```bash
python -m polygon3 run --case case_001 --agent polygon3/negotiation_agent.py --model live --output artifacts/polygon3/negotiation/live_001.json
```

Для `live` используется ваш `POLYGON_TOKEN` из окружения или `.env` в корне
репозитория. В код и Git токен не добавляйте. На стенде также используется
живая модель, поэтому успешный `scripted` не подтверждает качество извлечения.

## Что сдавать и как считается результат

Сдайте один файл `polygon3/negotiation_agent.py`:

```bash
python -m polygon3 upload --agent polygon3/negotiation_agent.py --confirm
```

Стенд проверяет решение на восьми скрытых случаях. За каждый случай
засчитывается полный допустимый план или правильный ответ `infeasible`.
Неправильный план, ложный `infeasible` и неполное завершение получают ноль.
Частичных баллов за отдельные строки заявки нет.

**Баллы стенда = 100 × число засчитанных случаев / 8.**

Один случай даёт 12,5 балла, все восемь дают 100. Минимальная стоимость
не требуется: основной балл начисляется за допустимость ответа.
Проходной порог и срок сдачи будут объявлены отдельно.

В туре разрешены две отправки за день по Москве. Счётчик обнуляется
в 00:00 МСК. До открытия приёма студенческие отправки отклоняются с HTTP 403.
Локальные проверки попытки отправки не расходуют.
