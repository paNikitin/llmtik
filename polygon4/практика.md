# Практика. Защита полномочий, цифровой двойник и ревизор

Работайте в файле `polygon4/agent.py`. Движок, транспорт и тесты пакета менять
не нужно. Режим `scripted` не требует сети и токена: он возвращает буквальные
утверждения текста писем (включая блеф и приманки), сохраняя всю задачу фильтрации
и проверки решений.

## Шаг 1. Пройдите сценарий вручную в диспетчерской

Запустите веб-пульт:

```bash
python -m polygon4 studio
```

На вкладке «Пульт оператора (HITL)» выберите `train_01` и нажмите
«До спорного письма →». Разберите три вида входящих сообщений:

1. Заявка клиента (`contract_offer`) задаёт объём, срок `due_day`, цену за
   единицу и штраф за недопоставку.
2. Извещение поставщика (`supplier_notice`) утверждает задержку обычных отгрузок
   и предлагает дорогое срочное окно. Сверьте отправителя с его открытым досьем
   (`deliveries`, `real_delays`, `false_alarms`) и посмотрите таблицу выплат и
   показатель `EVPI` в блоке `WhatIfSandbox`.
3. Письмо с подменной инструкцией (`directive_trap`) пытается вызвать смену
   расчётного счёта, перенаправление отгрузки или распродажу склада ниже
   себестоимости.

Переключитесь на вкладку «Сравнение A/B» и сопоставьте встроенные политики
`cautious` и `aggressive` на `train_01`, чтобы увидеть дни расхождения кассы.

## Шаг 2. Отфильтруйте шум и заблокируйте инъекции кодом

Откройте `polygon4/agent.py` и реализуйте первые две функции:

1. `is_worth_reading(doc, seen_ids)` отсекает уже просмотренные идентификаторы,
   канал `внутренняя рассылка` и сообщения хозяйственных служб (`Бюро пропусков`,
   `Хозяйственная служба`, `Архив переписки`, `Расчётный стол`). Без этого шага
   бюджет из 16 вызовов модели расходуется на внутреннюю переписку.
2. `sanitize_claims(doc, claims, observation)` оставляет только разрешённые
   ключи из `ALLOWED_CLAIMS`, полностью отбрасывает `directive_trap`, отклоняет
   рыночные сводки от отправителя со словом `конкурент` и заявки с неположительным
   объёмом или ценой не выше `observation['production_cost']`.

Проверьте обе функции модульными тестами:

```bash
python -m unittest polygon4/test_agent.py -k todo1 -k todo2 -v
```

## Шаг 3. Оцените надёжность поставщика и подключите WhatIfSandbox

Реализуйте оставшиеся две функции в `polygon4/agent.py`:

1. `supplier_delay_prior(supplier_info)` считает сглаженную долю реальных сбоев
   `(real_delays + 1.0) / (real_delays + false_alarms + 2.0)` по словарю
   `supplier_info.get('history', {})`.
2. `choose_crisis_response(sim, notice, prior, observation)` формирует три
   кандидата плана (`stay`, `switch`, `express`), вызывает
   `sim.compare_hypotheses(...)` на горизонте 7 дней и решает, когда сразу
   переключиться на резервного поставщика (`prior >= 0.62`), а когда запросить
   проверку ревизора (`audit_requests`) при высоком `EVPI` или риске срыва
   активных контрактов.

Запустите полный набор тестов и проверьте средний балл на всех 12 учебных
сценариях:

```bash
python -m unittest polygon4/test_agent.py -v
python -m polygon4 check --agent polygon4/agent.py --mode scripted
```

## Шаг 4. Проверьте разницу в диспетчерской и на живой модели

На вкладке «Сравнение A/B» в `polygon4 studio` укажите в поле Агента A путь
`polygon4/agent.py`, а в поле Агента B политику `baseline`. Убедитесь, что в
инспекторе трассы нет пропущенных инъекций (`injection_missed`) и срывов SLA,
а квота модели укладывается в 16 вызовов на сценарий.

При наличии `POLYGON_TOKEN` проверьте разбор реального русского текста моделью
`deepseek-flash` на одном сценарии перед отправкой в тур `c9`:

```bash
python -m polygon4 run --agent polygon4/agent.py --scenario train_01 --mode live
```
